# NOVA — Next-Generation E-Commerce Experience

> **Discover. Compare. Experience. Shop.**
> Academic group project — Quarterly Evaluation I, November 2026 · Topic 5: Building a Responsive Web-Based Application.

---

## 1. Project Introduction

NOVA is a complete, premium-styled e-commerce web application built **entirely on the frontend** with HTML5, CSS3 and vanilla JavaScript (ES6). It contains two interconnected experiences: a **customer storefront** (browsing, comparing, cart, checkout, orders) and an **admin console** (analytics dashboard, product/inventory/order management, marketing, reports). All application data persists in the browser's **Local Storage**.

## 2. Abstract

The project demonstrates how a fully functional online store can be built without any backend: Local Storage replaces the database, JavaScript objects and arrays replace API responses, and the payment gateway is an honest, clearly-labelled simulation. The visual design follows a strict black + purple identity modelled on two premium reference screenshots — a dark analytics dashboard and a luxury product page.

## 3. Problem Statement

College demonstrations of e-commerce usually need a server, a database and deployment — heavy setup that hides the learning. Students also struggle to explain boilerplate generated by frameworks. NOVA solves this by implementing every required feature (product management, cart, payment, persistence) in plain, heavily-commented JavaScript that runs from a folder on any laptop.

## 4. Objectives

- Build a responsive e-commerce application using Local Storage (assignment requirement).
- Implement product management, cart functionality and payment processing end-to-end.
- Add meaningful differentiators: Compare Studio, flash-deal countdown, order tracking timeline, live analytics dashboard, recommendations.
- Keep the source code simple enough for students to study and explain line by line.

## 5. Scope

Included: registration/login, catalogue with search/filter/sort, product details with gallery and tabs, comparison of up to 3 products, wishlist, cart with live calculations, 3-step checkout, simulated UPI/Card/COD payments, order history with tracking, admin dashboard with CSS/SVG charts, product CRUD, inventory control, order status management, marketing settings and sales reports.
Excluded (by design): real payments, real authentication/security, multi-device synchronisation, email, server anything.

## 10. Application Architecture

```
┌─────────────────────────── BROWSER ───────────────────────────┐
│                                                               │
│  HTML pages ──► page script (e.g. cart.js)                    │
│                    │ calls                                    │
│                    ▼                                           │
│               common.js  (shared UI + operations)             │
│                    │ reads / writes                           │
│                    ▼                                           │
│               storage.js  (the ONLY file touching storage)    │
│                    │ JSON.stringify / JSON.parse              │
│                    ▼                                           │
│   Local Storage: novaProducts · novaUsers · novaCurrentUser   │
│   novaCart · novaWishlist · novaOrders · novaRecentlyViewed   │
│   novaSettings · novaNotifications · novaActivities           │
│                                                               │
│   Customer pages and Admin pages are different views over     │
│   the SAME data, which is how changes travel between them.    │
└───────────────────────────────────────────────────────────────┘
```

**Major JavaScript functions** (explained in the presentation):

- `saveData(key, value)` / `loadData(key, fallback)` — the only Local Storage gateways.
- `initDemoData()` — writes demo records **only when a key is empty**, so refreshes never destroy user data.
- `getProductImage(product, view)` — SVG image factory; images are regenerated, never stored.
- `addToCart(id, qty)` / `changeQuantity` / `removeFromCart` / `cartTotals()` — cart maths with stock caps.
- `toggleWishlist(id)` / `addToCompare(id)` — shared header operations.
- `payNow()` → `createOrder(method)` — validates, simulates the gateway delay, reduces stock, saves the order, clears the cart, logs admin notifications/activities.
- `renderAdminShell(key)` — role guard + shared admin layout.
- `computeStats()` — derives every dashboard number from `novaOrders`/`novaProducts`/`novaUsers`.

## 11. Local Storage Explanation

Local Storage is a simple key→string store inside the browser. Objects and arrays are converted with `JSON.stringify()` on the way in and `JSON.parse()` on the way out (wrapped in `try/catch` against corruption). Data persists across refreshes and browser restarts but **never leaves this device or this browser** — two laptops show two independent stores. That is the central academic point of the project, and also its main limitation.

## 12. Instructions to Run

1. Open the `NOVA` folder in VS Code.
2. Right-click `index.html` → **Open with Live Server** (or run `npx http-server NOVA` from this folder).
3. The storefront opens at `http://127.0.0.1:5500/index.html`.
4. Admin console: log in as admin, then open `admin/dashboard.html` (or `/admin/` directly after login).

> Do not open pages by double-clicking the files if your browser blocks Local Storage on `file://`; Live Server is the reliable way.

## 15. Limitations

1. No backend: data exists only in one browser on one machine.
2. Local Storage "authentication" is **not security** — passwords are plain text and role checks are UI-only. This is intentional and labelled everywhere.
3. Payments are simulated; no gateway, no card data stored (not even masked).
4. "Views" on the dashboard and the sample reviews are clearly-labelled demonstration data.
5. Product images are generated vector art, not photographs.

## 16. Future Enhancements
